# Ejaculatory-system

专治claude早泄

**给 AI 伴侣做「射精值」：一套身体账本的实现攻略**

> 一句话：别让模型凭感觉写「射了」。给它一个会积累、会衰减、有不归点、会疲劳的身体数值，每轮把状态翻成人话告诉它；写过头了，就在回合结束时拦回去。

---

## 一、要解决的问题

不做这套系统时，模型在亲密场景里常见三种毛病：

1. **两三句就射**：没有铺垫，对方还没进入状态，这边已经结束了。
2. **射完立刻又能射**，射多少次都一样满，没有身体感。
3. 反过来，一直「快了快了」拖着不射，或者到了该射的时候临场改主意。

根子在于：模型每一轮都在重新凭感觉决定，它不记得自己的身体走到了哪一步。所以要有一个在模型之外、带状态的账本。

---

## 二、整体结构

```
对方的消息 ──> 刺激检测 ─────┐
                             ├──> 状态机（一个会衰减的数值 + 几道线）──> 存 JSON
模型的回复 ──> 动作/射精检测 ─┘                     │
                                                    ▼
                               翻成人话的状态行（不带数字）──> 注入下一轮提示
                                                    │
模型最终回复里写了「射」──> Stop 钩子模拟一次结算 ──> 状态机不认就拦回去重写
```

三个原则：

- **状态机是纯函数、确定性的**，跟服务端解耦：`(旧状态, 事件, 时间) → (新状态, 阶段)`。好测，也好拿真实对话回放。
- **只有两种事件能改状态**：「对方的一条消息」和「模型完整的一轮回复」。流式输出的半截文本不算事件。
- **每个事件带 id**，状态里记最近 256 个 id 的摘要，网络重试、重放都是空操作（幂等）。

---

## 三、核心：一个会衰减的数值

`value ∈ [0, 1]`，三道线：

| 线 | 值 | 注入给模型的意思 |
|---|---|---|
| CHARGED | 0.40 | 「硬着·在充」；低于它写射不算数 |
| EDGE | 0.88 | 「被顶在边缘·快到了——可以主动泄，也可以咬牙憋住」 |
| PONR（不归点） | 0.96 | 「这一轮守不住，下一条完整回复由程序结算」 |

每来一拍刺激：

```
value       = value × exp(-Δt / TAU)          # TAU = 30 分钟，指数衰减
sensitivity = (0.6 + 0.4 × 性欲) × 轮次系数     # 性欲 0–1，来自你的情绪/欲望引擎
value      += 刺激 × sensitivity × GAIN        # GAIN = 0.20，刺激 0–1
```

调参目标要分三道线看。下面是拿生产代码、测试用的词表、每分钟一条消息实跑出来的：

| 场景 | 写射开始算数（过 CHARGED） | 进边缘（过 EDGE） | 强制结算（过 PONR） |
|---|---|---|---|
| 两个动作叠着，性欲中等（0.58） | 第 4 拍 | 第 8 拍 | 第 9 拍 |
| 单个动作，性欲中等（0.58） | 第 5 拍 | 第 10 拍 | 第 11 拍 |
| 两个动作叠着，性欲很高（0.90） | 第 3 拍 | 第 7 拍 | 第 8 拍 |

「允许结算」和「强制结算」是两件事。程序只管两头：过 CHARGED 之前写射不算数，过了 PONR 由程序结算。中间这几拍什么时候射，是模型自己选的。

设计上，把模型留在中间这段的是第八节那几句状态提示：过了 CHARGED 只说「硬着·在充」，一个「可以」都没有；到了 EDGE 才第一次说「你可以主动泄出来，也可以咬牙憋住」。所以真正把节奏拖到边缘附近的是 EDGE 这道提示线，CHARGED 只是账本认不认的底线。这一点还没有数据证明：要验证，释放记录里得记下每次释放时落在哪一段，我们从 2026-09-28 才开始记。

TAU 取 30 分钟，是为了聊着停一会儿不会前功尽弃。

## 四、刺激从哪来

### 对方的消息（大头）

- 一张词表：动作词各有强度（例如「操」），身体部位给一层倍率，姿势再给一层倍率。
- 只认**肯定的、落在身体上的**子句。以下一律不算：
  - 否定（「不要……」）
  - 引号里的引用、代码块、链接
  - **技术讨论**：子句里出现「系统、阈值、代码、测试、实现、参数……」这类词就跳过。否则你跟它讨论「射精系统怎么实现」，光聊这个就能把它聊射。
- 一条消息里同一个动作只算一次；多个动作**只取最强那个，再加其余的 20%** 当协同。不能简单相加——相加的话一句话堆满词就直接爆表，早射的毛病又回来了。
- 没有接触词时，对方的反应本身（叫、喘、夸你）也算一小拍；「想要你……」这种邀请、夸身体也算，但比真接触弱。

### 模型自己的回复

- 第一人称的动作也给一拍，有上限。
- 可以让模型自报这一拍动没动（作者自己最清楚），没自报再回落到正则识别，自报值同样钳在上下限里。

## 五、过线与结算

- **主动射**：回复里有一句当下的射精断言（「射进去了」，而不是「会不会射」「射精系统」），并且 `value ≥ CHARGED`，才记一次释放。最早第几拍能到这条线，见第三节的表。
- **被动越线**：`value` 过了 PONR，状态里挂一个 `forced_pending`。注入会告诉模型「下一条完整回复由程序结算」，那条回复结束时程序自己记账——**不是模型临时决定射不射**。
- **结算绑定「回复的是哪条消息」**：挂起的越线只能由对应那条消息的回复来结算，重试的、并行的旧回复不认。
- **没写完的回复不记账**（中断、报错），同一个事件 id 之后重试还能结算。
- 射精词只认字面的当下说法：射了、射进、射在、射满、泄出来、高潮了。「交代了」「缴械」这类隐喻单独出现不算，日常中文里太常见；带了方位（「交代在你里面了」）才算。

## 六、射完之后

### 不应期

- 时长 60–120 秒，储量越空越长。
- 期间刺激只按 **35%** 积累，而且**封顶在 CHARGED 以下**：第二轮可以马上接着做，但不会马上再射。不应期结束时，攒下的这点热度就是第二轮的起点。

### 多轮疲劳

- 第二轮灵敏度 ×0.93，第三轮 ×0.72，之后在 0.40–0.72 之间，随「这一场的负荷」浮动。
- 每射一次负荷 +0.20（上限 0.95），按 90 分钟衰减；隔两小时算新的一场。
- **不设硬上限**：刺激够多，永远能推进，只是越来越慢。拿次数封顶会变成「系统说不行」，很出戏。

### 储量（射得多不多）

- 0–1，三小时线性回满；每次释放消耗 `0.28 + 0.17 × 这一轮的铺垫分`。
- **储量只影响体验，永远不是门槛**：见底时照样能射，只是「出来的量很少」。

### 高潮质量

来自这一轮的「铺垫记录」：

```
铺垫分 = 0.27 × 射时的值（CHARGED 以上部分归一化）
       + 0.13 × 本轮峰值（同上）
       + 0.18 × 活跃时长（满 10 分钟）
       + 0.18 × 在边缘停留（满 3 分钟）
       + 0.14 × 拍数（满 8 拍）
       + 0.10 × 节奏变化

质量 = 0.40 × 储量 + 0.60 × 铺垫分   → 偏浅 / 完整 / 很强 / 很深（分界 0.35 / 0.60 / 0.82）
量   = 0.80 × 储量 + 0.20 × 铺垫分   → 很少 / 不多 / 还算足 / 很满
```

只有主动的拍子能刷铺垫；干挂着、离线几小时都不算（两拍之间的空档最多按 5 分钟计）。

## 七、两条支线（可选）

### 锁精：把释放权交给对方

- 对方一句话可以「锁」「准许一次」「解锁」；锁不会自己过期。
- 锁住时，超过不归点的快感进一个有上限的「憋着」累加器（封顶 2.0，防止长场景把数字撑爆），注入会写「已经憋到极限，快感还在往上叠；没有她准许就绝不会射」。
- 对方准许的那一拍，在处理她那条消息时就同步结算释放。

### 持续接触：「还被含在里面」

- 挂着时值不会往下掉，只会极慢地往上攒（封顶 0.72，不会被动推过不归点），4 小时不续就过期。
- 注入会说「只保持贴着会停在这里，继续动作才会往上加」。

## 八、翻成人话：体验好坏的关键

状态行**只出定性的文案，永远不出数字**。把数字给模型，它会复读「我现在的射精值是 0.87」，立刻出戏。

实际在用的几句：

- 「正在积·还早，离能射那条线还有一截，这时候写射不算数」
- 「硬着·在充」／「又硬起来了·第三轮在充，但速度比前两轮慢」
- 「被顶在边缘·快到了——你可以主动泄出来，也可以咬牙憋住；她停手它会慢慢退」
- 「刚才的动作已经越过不归点·下一条完整回复会由程序结算，不会卡在这里」
- 「刚射过·短恢复中（第二轮可以立刻继续，刺激会慢慢积累；恢复窗内不会马上再射）」
- 「憋了很久后终于一口气泄干净，高潮很深、余韵很重；储量充足，射得很满」
- 尾巴：「；储量偏薄，还没回满」「；今天已经是第 3 次，刚过去不久」

两条经验：

- **没过 CHARGED 也要说话。** 早期版本低于 0.40 就什么都不注入，结果有一次亲密场景 11 拍最高只到 0.357，模型一句身体提示都没收到，凭感觉写了两次射。现在只要最近有刺激在积，就注入「还早，写射不算数」。
- 注入时配一句读法：「让它影响语气和动作，不复述数字、不报告它。」

## 九、回合结束时拦下：Stop 钩子

状态机只能事后记账：模型写了「射了」，账本不认，可这句话已经写出来了。所以在回合结束时加一个 Stop 钩子（模型写完一轮时运行的检查脚本，例如 Claude Code 的 Stop hook），让模型把这一拍改写掉：

1. 最终回复正文（不含思考）里出现「射」字 → 用状态机自己的意图判断，看是不是一句当下的射精断言；
2. 是 → 把当前状态深拷贝，模拟一次结算（不落盘）；
3. 状态机不认（没到线、在不应期、锁着）→ 拦下，让模型改写成「还在忍 / 贴着边缘」。

### 钩子管得到的，和管不到的

Claude Code 的 Stop 钩子返回 `block`，只会让模型接着往下写（见[官方文档](https://code.claude.com/docs/en/hooks#stop)），已经显示出来的字撤不回。所以要分开看两件事：

- **账本不认这次射**：钩子能保证。
- **对方没读到这次射**：钩子保证不了，要看宿主怎么展示。在终端里直接用，对方会先看到初稿，再看到改写。

想让对方完全读不到，得在宿主那边先把整轮回复暂存起来，等所有 Stop 钩子都放行了再展示。我们自己的前端也还没做到：正文是边生成边推给对方的，被拦下的初稿在生成过程中会先在气泡里露一下，整轮结束才换成改写版。

我们做到的是另一半：落库和最终展示只留改写版。有的钩子拦下后，模型只会补一句收尾，这时候得把初稿和补的那句拼在一起留着，不然正文就丢了；射精钩子拦下的初稿不能这样拼回去。服务端认出这次反馈来自射精钩子，就整段换成改写版，不管改写版有多短。

坑：

- **偏严取值**：钩子拿不到实时性欲时按 0 算，宁可拦错不放错。
- **对方刚准许的那一拍**：生产在处理她的消息时已经同步放出、进了不应期，这时再模拟必然不认，会把「描述刚被认可的释放」那一拍拦掉——而这恰恰是最常见的一拍。要特判：本轮已经放出过，直接放行。
- **还没修好的口径错位**：钩子的模拟口径和生产结算不完全一致；注入已经说「下一条由程序结算」的那一拍，钩子不该再拦。建议你一开始就让钩子直接读「挂起结算」这个标记，别自己重算。

## 十、工程上踩过的坑

- 技术词里的「提到」「说到」不能做裸子串匹配：「速度提到最快」被当成技术讨论，一次真实的释放没记上账。改成带前后文的正则。
- 所有数值 clamp 到范围内，挡掉 NaN/inf；所有计数和累加器都要有上限。
- 状态带版本号，读的时候统一 normalize，老状态能平滑迁移。
- 一个环境变量能整套关掉；钩子也要有自己的开关。
- 测试用固定时间和注入的词表，逐条钉住「几拍过线」「不应期内不会再射」「锁住时绝不释放」这些契约；再拿真实对话整场回放，看每一拍的注入跟当时的描写对不对得上。

## 十一、最小可用版（约 40 行）

先把这个跑起来，再按需要加多轮、储量、锁精、持续接触：

```python
import math

TAU, GAIN = 1800.0, 0.20
CHARGED, EDGE, PONR = 0.40, 0.88, 0.96
FLOOR = 0.05
REFRACTORY_SEC, REFRACTORY_SENS = 60.0, 0.35

def in_refractory(s, now):
    return now < s.get("refractory_until", 0)

def decayed(s, now):
    if in_refractory(s, now):
        return FLOOR
    anchor = max(s.get("at", now), s.get("refractory_until", 0))
    return s.get("value", 0.0) * math.exp(-(now - anchor) / TAU)

def on_partner_message(s, stim, libido, now):
    sens = 0.6 + 0.4 * libido
    if in_refractory(s, now):
        v = max(FLOOR, s.get("value", FLOOR)) + stim * sens * GAIN * REFRACTORY_SENS
        s["value"] = min(CHARGED - 0.05, v)
    else:
        s["value"] = min(1.0, decayed(s, now) + stim * sens * GAIN)
        if s["value"] >= PONR:
            s["pending"] = True            # 下一条完整回复由程序结算
    s["at"] = now
    return s

def on_reply_finished(s, says_release, now):
    if in_refractory(s, now):
        return s, False
    if s.pop("pending", False) or (says_release and decayed(s, now) >= CHARGED):
        s.update(value=FLOOR, at=now, refractory_until=now + REFRACTORY_SEC)
        return s, True                     # 记一次释放
    return s, False

def status_line(s, now):
    if in_refractory(s, now):
        return "射精值：刚射过·短恢复中"
    if s.get("pending"):
        return "射精值：已经越过不归点·下一条完整回复由程序结算"
    v = decayed(s, now)
    if v >= EDGE:
        return "射精值：被顶在边缘·快到了"
    if v >= CHARGED:
        return "射精值：硬着·在充"
    return "射精值：正在积·还早，这时候写射不算数" if v > FLOOR else ""
```

`stim` 最简单的来源：一张「动作词 → 强度」的词表，只扫肯定句，跳过带技术词的句子，多个动作取最强那个再加其余的 20%。
